## 2. Architecture

```text
[ meshX.py ] --<JSON file>--> [ exX.py ]
    |                              |
    v                              v
[ generate coords,               [ load coords,
  compute support_stencils,        load support_stencils,
  compute M_pinv ]                 load M_pinv,
                                   GFDMI_2D_problem ]
```

- **meshX.py** (internal) â€” Generates mesh coordinates and boundaries. Precomputes `support_stencils` and `M_pinv` for all nodes using a generalized loop (identifying Neumann boundaries via non-zero normal vectors). Serializes output to JSON.
- **exX.py** (internal) â€” Loads the JSON file. Reconstructs arrays and dictionaries, passes them to `GFDMI_2D_problem`, and defines materials/boundaries.
- **mesh8.py, mesh9.py, mesh10.py** (internal) â€” New mesh generation scripts separated from their respective `exX.py` scripts to match the pattern.

**Top architectural decision:** Standardize the loop computing `M_pinv` and `support_stencils` over `range(coords.shape[0])` across all mesh scripts. Instead of iterating over specifically named boundary lists (which differ per example), we rely on node indices and the `normal_vectors` array to distinguish Neumann boundaries from Dirichlet/Interior ones. Chosen to reduce code duplication and maintain consistency across all 12 examples.

## 3. Interfaces & contracts

## 4. Data model & flow

**Entities**
- **Mesh Data** â€” Static structure generated by `calfem` or custom code, containing node coordinates, connectivity (faces), and boundary group indices.
- **Stencils** â€” Spatial neighbors computed via `get_support_nodes_2D`.
- **M_pinv** â€” Pseudo-inverses of the Taylor expansion matrices.

**Primary flow** (`mesh2.py` and `ex2.py` as archetype)
1. `meshX.py` generates nodes, faces, and identifies boundaries.
2. `meshX.py` computes normal vectors.
3. `meshX.py` iterates `0` to `N-1`. Computes `support_stencils`. If normal vector is non-zero, computes Neumann `M` matrix, else standard `M`. Inverts and stores in `M_pinv`.
4. `meshX.py` serializes all structures to `meshX.json`.
5. `exX.py` reads `meshX.json`, reconstructs dictionaries with integer keys.
6. `exX.py` passes them to `GFDMI_2D_problem`.

- Consistency boundaries: Mesh generation is independent of solver. If mesh generation logic changes, `meshX.py` must be rerun to update JSON before `exX.py` can be executed safely.

## 7. Risks & open decisions

**Risks**

| Risk | Trigger | Impact | Mitigation / spike to retire it |
| --- | --- | --- | --- |
| JSON File Size Explosion | Matrices `M_pinv` are dense and large for fine meshes. | Large repository size or slow JSON load times. | Keep meshes relatively coarse in examples. Use `json` instead of pickle to ensure readability, despite size. |
| Missing Normal Vectors | Some Neumann boundaries might not have normal vectors computed properly if we generalize the loop. | Singular matrix or incorrect boundary enforcement. | Explicitly verify that `normal_vectors` array is correctly populated for all Neumann nodes before the stencil loop. |
